# План реализации Medora (лабораторная работа №4)

Документ фиксирует приоритизацию системных требований, оценку трудозатрат, планы по итерациям после согласований с заказчиком и итоговую смету.

## 1. Исходная приоритизация функционала

Шкала приоритетов: **10** (наивысший) … **50** (минимальный).

| ID | Функция | Priority | Обоснование |
|---|---|---|---|
| REQ-FUNC-001 | Регистрация и вход | 10 | Must have: без аккаунта нет персональных данных |
| REQ-FUNC-002 | Управление списком лекарств | 10 | Must have: ядро предметной области |
| REQ-FUNC-003 | Расписание приёма | 10 | Must have: основа ежедневного сценария |
| REQ-FUNC-004 | Отметка приёма / пропуска | 10 | Must have: ключевое действие пользователя |
| REQ-FUNC-009 | Изоляция данных | 10 | Must have: безопасность и доверие |
| REQ-FUNC-005 | Напоминания о приёме | 20 | Should have |
| REQ-FUNC-006 | Уведомления о пропущенных дозах | 20 | Should have |
| REQ-FUNC-007 | Учёт остатков | 20 | Should have |
| REQ-FUNC-008 | История приёма с фильтрами | 30 | Could have |
| Email/SMS-напоминания | (вне текущего ID, post-MVP) | 50 | Won't have for MVP (дорого по интеграциям) |

## 3. План после раунда 1

По итогам переписки заказчик согласился:

* оставить в MVP напоминания **в UI + Web Push**, без email/SMS;
* упростить историю до фильтра по периоду и препарату (без сложных отчётов);
* не включать семейный доступ на этом шаге (ещё не запрашивался).

## 4. Итоговый план после раунда 2

Заказчик добавил **режим опекуна** (`REQ-FUNC-010`, priority **10**) и отказался сдвигать deadline. Согласовано привлечение **junior-разработчика на 2 недели**.

| Спринт | Длительность | Функции | Ожидаемый результат |
|---|---|---|---|
| 1 | 2 недели | FUNC-001, FUNC-002, FUNC-009 | Auth + справочник лекарств |
| 2 | 2 недели | FUNC-003, FUNC-004 | Расписание и отметки |
| 3 | 2 недели | FUNC-007, FUNC-005, FUNC-006 | Остатки и уведомления |
| 4 | 2 недели | FUNC-008 + **FUNC-010** (junior на UI опекуна) | История + приглашение опекуна, просмотр расписания подопечного, уведомления о пропусках |
